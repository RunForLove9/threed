# Feature Specification: Three.js 核心运行时底座（版本基线 + 场景/组件/交互 + 可序列化 Schema + SDK 骨架）

**Feature Branch**: `001-threejs-core-runtime`

**Created**: 2026-11-05

**Status**: Draft

**Input**: User description: "请帮我选用一个基准的 three.js 的较新的稳定版本，然后设计底座核心运行时（场景/组件/交互系统 + 可序列化 schema + SDK 骨架）"

**涉众角色**:

- **底座工程师**（平台维护者）：锁定内核版本、建设并演进运行时
- **内容/业务开发者**（SDK 使用方）：基于 SDK 搭建场景、注册组件、声明交互、持久化内容
- **CI / 自动化测试**（无头消费者）：契约测试、渲染回归、序列化往返验证

## Clarifications

### Session 2026-11-05

- Q: 序列化场景文档中的每个组件实例是否携带稳定唯一 ID，由谁分配？ → A: 携带——创建时由系统分配文档内唯一 ID，写入序列化数据并往返保持不变，允许创建时显式指定；事件载荷与定点编辑以该 ID 引用实例。附带约束：schema 面向"可保存、可恢复、可加载"的持久化场景设计，保持存储无关。
- Q: 背景、雾等全局视觉设置在 v1 场景文档中以什么形态承载？ → A: 环境也是组件——内置环境组件（背景/雾等全局视觉）挂载于场景树；文档顶层仅 schema 版本 + 元数据 + 组件实例树，序列化只有一种节点形态，不设并列的全局设置块。
- Q: 用户自定义组件的 props 允许取哪些类型的值？ → A: 仅 JSON 兼容值（null/布尔/数字/字符串/数组/对象，递归）；契约声明各字段类型与默认值，非 JSON 兼容值（函数、类实例、循环引用等）在注册与写入时拒绝；颜色/向量等富语义以数组/对象表达。
- Q: 指针拾取事件命中组件实例后如何传播？ → A: 仅命中实例派发——订阅方可全局订阅或按组件 ID/类型定向订阅，v1 无冒泡；未来如引入冒泡 MUST 作为增量兼容扩展。
- Q: v1 公共交互事件契约包含哪一组事件类型？ → A: 最大扩展集 + 定向简化——指针 enter/leave/down/up/click、滚轮、键盘（keydown/keyup，标准键值）、相机控制变更事件全部纳入契约；定向简化：不含逐帧 pointermove，键盘不做输入法/组合键语义，相机变更为粗粒度节流通知（不承诺逐帧增量载荷）；全部事件必须可在无头环境确定性模拟。

### Session 2026-11-06

- Q: 三包（core/sdk/http）的发布渠道是什么——公共 npm、私有 registry，还是仅本地消费？ → A: **本地可用优先**——v1 不向任何 registry 发布；唯一消费形态为 monorepo 本地引用（仓库内 `pnpm --filter`、跨仓库 `file:` 协议 / `pnpm link`）。npm 发布（公有/私有）为后续独立功能，立项时再决策渠道、账号与发布流程。FR-013 的"随 SDK 一同发布"在 v1 语境 = 类型定义随包构建产物（dts）一同交付，不预设 registry 发布；quickstart 与各 README 的安装示例必须与本地消费形态一致。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 基线版本锁定与最小场景运行时 (Priority: P1)

作为底座工程师，我要在唯一依赖声明处锁定 three.js 基线版本（**0.186.1**），并提供一个能创建、运行、销毁渲染运行时的最小 SDK，使后续一切能力都构建在同一个受控内核之上。运行时需提供：挂载到浏览器画布或无头环境、空场景首帧渲染、每帧基础性能度量（帧率、draw call、三角形数、内存）、以及销毁时的资源释放。

**Why this priority**: 这是宪法原则 II（单一渲染内核）与遗留 TODO #2（版本锁定）的直接落点；没有版本基线与可启动的运行时，其余一切能力无从构建、无从验证。它同时是可独立演示的最小 MVP（空场景也能渲染与度量）。

**Independent Test**: 在无头环境中用 SDK 创建运行时 → 渲染空场景 → 产出首帧截图并与黄金图比对 → 销毁后确认无资源残留；配合 CI 校验仓库内 three.js 版本唯一性，即可独立验证本故事。

**Acceptance Scenarios**:

1. **Given** 一个空项目，**When** 开发者按文档引入 SDK 并以不超过 5 个核心概念（运行时/场景/相机/渲染循环/销毁）启动运行时，**Then** 浏览器与无头环境均能产出首帧且无报错。
2. **Given** 仓库任意子项目，**When** 安装依赖并校验 three.js 解析版本，**Then** 全仓库仅解析出一个版本（0.186.1），CI 版本唯一性检查通过。
3. **Given** 一个正在运行的空场景，**When** 查询性能度量，**Then** 可获得帧率、draw call 数、三角形数、内存占用四项指标的当前值。

### User Story 2 - 数据驱动的组件与场景系统 (Priority: P2)

作为内容开发者，我要使用注册表中的组件、以嵌套组合的方式搭建场景结构，使我全程无需接触渲染内核即可表达"什么在场景里、以什么属性存在"。系统需提供组件注册机制（唯一类型标识 + props 契约）、场景树管理（增删改查、父子层级与空间变换语义）、以及一套内置基础组件。

**Why this priority**: 宪法原则 IV（可组合组件体系）的落点，注册表是底座核心资产；场景的创建/编辑先于序列化（被序列化的对象就是这棵组件树），也先于交互（交互挂在组件上）。

**Independent Test**: 仅用内置组件通过 SDK 调用搭建一个嵌套 ≥3 层的场景，并对每个内置组件跑独立的渲染冒烟测试，即可独立验证本故事（不依赖序列化与交互能力）。

**Acceptance Scenarios**:

1. **Given** 一个已注册的组件类型，**When** 开发者创建实例并传入 props，**Then** props 按契约校验通过后实例进入场景树；非法 props 被拒绝并给出可读、可定位的错误。
2. **Given** 场景树中存在嵌套组件，**When** 调整父级变换，**Then** 子级世界变换按层级语义正确跟随。
3. **Given** 一个未注册的类型标识，**When** 尝试创建实例，**Then** 系统明确报错且场景状态不变。
4. **Given** 内置基础组件集，**When** 逐一渲染冒烟测试，**Then** 全部通过（每个组件可脱离具体场景独立测试）。

### User Story 3 - 可序列化场景 Schema 与无损往返 (Priority: P3)

作为内容开发者与上层工具链，我要把任一场景状态导出为带 schema 版本号的声明式数据，并能仅凭该数据在全新运行时中重建等价场景，使场景可持久化、可网络传输、可版本比对——这也是协同编辑、回放、资产复用等地基。

**Why this priority**: 宪法原则 III（数据驱动与可序列化）的落点，且是遗留 TODO（API 形态之外最重要的契约）。置于组件系统之后：序列化的对象是组件化的场景树；置于交互之后交付亦可，但 schema 需为交互组件预留位置，故紧随 Story 2。

**Independent Test**: 构造一个覆盖全部内置组件类型、嵌套 ≥3 层的场景，序列化 → 新建运行时 → 反序列化，自动化深度比对场景树结构与 props 100% 等价；同一数据重复反序列化结果确定（幂等）。全程不需要交互系统参与。

**Acceptance Scenarios**:

1. **Given** 任一通过合法公共 API 构建的场景，**When** 序列化，**Then** 产出带 schema 版本号的声明式数据，且不包含隐藏运行时状态（内部缓存、GPU 资源句柄等）。
2. **Given** 一份序列化数据，**When** 在全新运行时中反序列化，**Then** 重建场景与原场景在结构与属性上深度等价（自动化比对通过）。
3. **Given** 一份旧 schema 版本的数据，**When** 用新版底座读取，**Then** 向后兼容直接读取成功，或给出明确报错并指向迁移工具（不静默出错）。

### User Story 4 - 声明式交互系统 (Priority: P4)

作为内容开发者，我要以组件/数据方式声明交互能力——相机控制（轨道等）、对象拾取、hover/click 等指针事件、键盘事件、相机控制变更通知——并通过订阅式 API 收到事件通知，使交互与场景结构一样可组合、可序列化、可迁移。

**Why this priority**: 交互是"物品设计/编辑/调整"类能力的公共底座，但依赖组件系统（拾取目标是组件实例）与运行时（事件循环）先就位；v1 只做声明式基础交互，高级交互（gizmo、框选等）留待后续功能。

**Independent Test**: 在无头环境模拟指针与键盘事件序列，验证拾取命中预期组件、事件回调信息完整（哪个组件、什么事件、什么位置/键值）；含交互声明的场景经序列化往返后交互等价生效。

**Acceptance Scenarios**:

1. **Given** 场景中挂载了相机控制组件，**When** 用户拖拽/缩放视口，**Then** 相机按该组件 props 定义的方式运动，且未挂载控制的运行时不受任何影响。
2. **Given** 场景中的可拾取组件，**When** 指针 hover 或点击其在屏幕上的投影区域，**Then** 订阅者收到至少携带目标组件标识、事件类型、命中位置信息的事件。
3. **Given** 一个含交互声明的场景，**When** 序列化并在新运行时中重建，**Then** 交互行为在新实例中等价生效。

---

### User Story 5 - 多包 SDK 骨架（core/sdk/http + 本地 Demo）与逃生舱 (Priority: P5)

作为业务与工具链开发者，我要拿到一个以 `core` / `sdk` / `http` 三包形态对外交付、TypeScript 类型完整、文档与示例齐全、且可本地一键启动实时渲染 Demo 的 SDK 骨架——其中包含显式标注的 three.js 逃生舱——使上层业务、编辑器与生成器可以立即开始对接，也使底座能力可以当场演示。

**Why this priority**: 宪法原则 I：一切能力以版本化、有文档的 API/SDK 暴露；骨架收纳前面所有故事的公共 API 面，故最后定型，但为每个前序故事提供发布出口。本地 Demo 同时是"底座可独立演示"（宪法原则 I）的常设载体。

**Independent Test**: 在一个独立的空项目中安装 `sdk` 包、按 README 示例跑通「启动 → 搭建 → 序列化 → 交互 → 销毁」全链路；本地一键启动 Demo 实时渲染；向 `http` 服务提交序列化场景数据换取渲染图像；TypeScript 类型检查零报错；公共 API 契约测试全部通过。

**Acceptance Scenarios**:

1. **Given** 发布的 `sdk` 包，**When** 开发者安装并运行官方示例，**Then** 示例开箱即用，无需阅读底座源码。
2. **Given** 一个高级需求，**When** 开发者使用显式标注的逃生舱 API，**Then** 能取到对应 three.js 原生对象，且文档明确声明该路径不承诺跨版本兼容。
3. **Given** 全部公共 API 面，**When** 运行契约测试与文档门禁，**Then** 每个 API 至少被一条契约测试引用且文档有条目，缺失即 CI 失败。
4. **Given** 检出的仓库，**When** 开发者执行 Demo 启动命令，**Then** 本地浏览器出现可交互的实时渲染演示，覆盖启动/搭建/序列化/交互主链路。
5. **Given** 运行中的 `http` 服务，**When** 客户端提交一份合法场景序列化数据，**Then** 在单请求超时上限内（v1 默认 30 秒；骨架级不承诺性能指标）收到该场景的渲染图像，且服务保持可用（不因单次请求崩溃）。

---

### Edge Cases

- three.js 集中升级后黄金图发生像素漂移：必须走带容差的比对 + 集中回归流程，不允许"顺手升级"（宪法原则 V）。
- 反序列化数据的 schema 版本**高于**当前运行时：明确报错并提示所需最低版本，不静默降级、不部分加载。
- props 含非法值（类型错误、越界、多余字段）：拒绝写入并给出定位到组件实例与属性路径的结构化错误。
- 同一类型标识重复注册：默认拒绝；如需覆盖必须显式声明覆盖意图，否则报错。
- 运行时销毁时的资源边界：底座创建的几何体/材质/纹理/事件监听必须释放；经逃生舱交出所有权的对象不释放（所有权边界必须写入文档）。
- 无头环境无 GPU 或上下文创建失败：显式报错或声明式降级（如软件渲染），不允许静默黑屏。
- 序列化数据被篡改/损坏：结构化校验错误（定位到字段），不允许抛出未捕获异常或崩溃。
- 空场景序列化：产出合法的最小场景文档，而非空文件或报错。
- 场景树出现循环引用：检测并报错（本期场景为树结构，不支持引用共享/实例图）。
- 组件在事件回调中修改自身导致的重入：必须有明确语义（如下一帧生效），不允许未定义行为。
- `http` 服务收到非法或超限的场景数据：返回结构化错误并保持服务存活，不崩溃、不悬挂。
- 同一运行时同时挂载多个相机控制组件：v1 明确报错拒绝（同一时刻至多一个激活相机控制），不静默叠加。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 底座 MUST 在唯一依赖声明处锁定 three.js 基线版本为 **0.186.1**，并由 CI 强制校验仓库内解析版本唯一（出现第二版本即失败）。
- **FR-002**: SDK MUST 支持创建、运行与销毁渲染运行时实例，同一套调用方式在浏览器与无头环境均可运行。
- **FR-003**: 运行时 MUST 内建并可随时查询四项基础性能度量：帧率、draw call 数、三角形数、内存占用。
- **FR-004**: 系统 MUST 提供组件注册机制：注册时 MUST 声明唯一类型标识与 props 契约（字段类型 + 默认值）；props 值域 MUST 限定为 JSON 兼容值（null/布尔/数字/字符串/数组/对象，递归），非 JSON 兼容值（函数、类实例、循环引用等）MUST 在注册与写入时拒绝；未注册类型 MUST NOT 可被场景引用。
- **FR-005**: 场景 MUST 表达为组件实例组成的树；组件实例 MUST 可嵌套组合，且父子空间变换语义明确、可预测。
- **FR-006**: 内置基础组件集 v1 MUST 至少覆盖：图元网格（立方体/球/平面等）、组（层级与变换）、材质属性、灯光（至少环境光 + 平行光/点光）、相机、环境（背景/雾等全局视觉，以组件形态挂载于场景树，不设文档级并列设置块）。
- **FR-007**: 系统 MUST 支持将任一场景状态完整序列化为带 schema 版本号的声明式数据；序列化结果 MUST NOT 依赖任何隐藏运行时状态，且 MUST 自包含、存储无关（可原样保存、恢复、加载于文件、数据库或对象存储，不假设特定存储介质或运行环境）。
- **FR-008**: 系统 MUST 支持仅凭序列化数据在全新运行时中重建等价场景，且等价性可由自动化深度比对（结构 + 属性）验证。
- **FR-009**: 序列化格式 MUST 携带显式版本号；格式 minor 变更 MUST 向后兼容；不兼容变更 MUST 提供迁移工具。
- **FR-010**: 交互能力（相机控制、对象拾取、hover/click 事件）MUST 以组件或数据声明方式表达，并可随场景序列化往返。
- **FR-011**: 交互事件 MUST 通过订阅式 API 暴露：拾取类事件 MUST 至少携带目标组件 ID（FR-020）、事件类型、命中位置信息；非拾取类事件（键盘/相机变更）MUST 携带事件类型与其对应数据。订阅方可全局订阅或按组件 ID/类型定向订阅，v1 事件传播无冒泡（仅命中实例派发 + 全局订阅），冒泡语义如未来引入 MUST 作为增量兼容扩展。
- **FR-021**: v1 公共事件契约 MUST 覆盖：指针 enter/leave/down/up/click、滚轮、键盘 keydown/keyup（标准键值，不含输入法/组合键语义）、相机控制变更（粗粒度节流通知，不承诺逐帧增量载荷）；逐帧 pointermove 不在 v1 契约（如引入 MUST 作为增量兼容扩展）；全部事件类型 MUST 可在无头环境确定性模拟并纳入契约测试。
- **FR-012**: SDK MUST 提供显式标注的 three.js 逃生舱入口；除逃生舱外，公共 API MUST NOT 泄漏渲染内核对象。
- **FR-013**: 公共 API MUST 附带 TypeScript 类型定义并随 SDK 一同发布。
- **FR-014**: 每个公共 API 面 MUST 有自动化契约测试；渲染 MUST 有无头冒烟测试与带容差的黄金图比对。
- **FR-015**: SDK 骨架 MUST 包含可运行示例、使用文档与可本地一键启动的实时渲染 Demo 应用；示例与 Demo MUST 覆盖 Story 1–4 的主链路（启动/搭建/序列化/交互）。
- **FR-016**: 运行时销毁 MUST 释放其创建的 GPU 资源与事件监听；经逃生舱交出所有权的对象除外，所有权边界 MUST 写入文档。
- **FR-017**: SDK MUST 以多包 monorepo 形态对外交付三个包：`core`（运行时内核：场景/组件/交互/序列化）、`sdk`（面向使用方的公共 API 门面：类型 + 文档 + 逃生舱入口）、`http`（基于无头运行时的渲染服务）；三包版本 MUST 统一治理，MUST NOT 出现包间版本漂移。
- **FR-018**: v1 MUST NOT 实现外部资产加载（glTF 等模型格式）；序列化 schema MUST 预留资产类组件的类型命名空间与字段草案（仅规范占位，v1 运行时不注册该族类型）；v1 的内容生产路径以程序化从零生成与渲染为主轴。
- **FR-019**: `http` 包 v1 MUST 提供骨架级最小能力：健康检查端点 +「提交场景序列化数据 → 返回渲染图像」端点；并发、鉴权、部署等生产化能力不在 v1 承诺范围。
- **FR-020**: 每个组件实例 MUST 携带文档内稳定唯一 ID：创建时由系统分配、允许显式指定、序列化往返保持不变；交互事件载荷（FR-011）与按 ID 定点读写 MUST 以该 ID 引用实例。

### Key Entities *(include if feature involves data)*

- **场景文档（SceneDocument）**: 顶层可序列化单元；仅包含 schema 版本号、元数据与组件实例树（全局视觉等一切内容由环境组件承载，不设并列设置块），是持久化与传输的最小完整单位。
- **组件定义（ComponentDefinition）**: 类型标识 + props 契约（字段类型与默认值，值域为 JSON 兼容值）+ 行为语义的自包含描述；注册后方可被公共 API 引用，是复用与演化的载体。
- **组件实例（ComponentInstance）**: 场景树节点 = 稳定唯一 ID + 类型标识 + props 值 + 子实例列表；ID 由系统分配（可显式指定）、文档内唯一、序列化往返不变，是事件引用与定点编辑的锚点；一切创建/编辑最终都落为实例数据的变更。
- **组件注册表（ComponentRegistry）**: 类型标识 → 组件定义的唯一映射；底座的核心资产，内置组件与第三方组件同一待遇。
- **运行时（Runtime）**: 绑定画布或无头渲染表面、驱动渲染循环、承载性能度量与事件分发的可创建/可销毁实例。
- **交互声明（InteractionComponent）**: 以组件形式表达相机控制、拾取目标与事件订阅的声明式交互配置。
- **Schema 版本（SchemaVersion）**: 序列化格式的独立版本标识，是兼容性承诺与迁移工具的锚点（独立于 SDK 包版本演化）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 一名未读过底座源码的开发者，依文档在 10 分钟内用 SDK 完成「启动运行时 → 搭建基础场景 → 序列化保存」并成功运行（以官方示例 + 新人演练验证）。
- **SC-002**: 对覆盖全部内置组件类型、嵌套 ≥3 层的场景，序列化 → 重建往返的结构与属性深度比对等价通过率 100%，且重复反序列化幂等。
- **SC-003**: CI 自动验证仓库内 three.js 版本唯一性（0.186.1）；全量契约测试与渲染黄金图比对（含容差）通过。
- **SC-004**: 底座在无任何业务接入的情况下可独立构建、独立测试、独立演示，三项流水线全部通过（宪法原则 I 的验收形态）。
- **SC-005**: 空场景连续运行 60 秒：性能度量四项指标全程可读，且内存无持续增长趋势（泄漏冒烟通过）。
- **SC-006**: 使用文档覆盖全部公共 API，且每个公共 API 至少被一条契约测试引用（文档-测试覆盖审计通过）。
- **SC-007**: `http` 渲染端点对标准测试场景数据返回有效渲染图像，连续请求下服务保持可用（自动化端到端验证）。

## Assumptions

- **版本基线选择依据**：截至 2026-11-05，npm `latest` 为 0.187.0（2026-10-30 发布，仅 6 天）；0.186.1 为上一 minor 线（0.186.x）最新 patch（2026-09-24 发布，约 6 周稳定期，含一个修补周期）。基线取"较新 + 已被社区验证"的平衡点 **0.186.1**；0.187.0 列为首次集中升级的头号候选，升级必须走宪法规定的集中回归流程。
- 语言与类型遵循宪法：核心代码 TypeScript，公共类型定义随 SDK 发布。
- 序列化格式采用 JSON（人类可读、可 diff、工具链生态最广）；schema 版本独立于 SDK 包版本演化。
- 运行环境：现代浏览器（桌面/移动）+ Node 无头环境（CI）；无头下降级路径（软件渲染或显式报错）在计划阶段确定。
- React/Vue 等框架绑定不在本期范围（骨架保持框架无关，绑定作为后续独立功能）。
- 交付形态（Q1 已决，2026-11-05）：`core` / `sdk` / `http` 三包 monorepo 对外暴露 + 本地一键启动实时渲染 Demo；`http` 为骨架级最小能力，生产化（并发/鉴权/部署）为后续功能。
- 发布渠道（2026-11-06 决策：本地可用优先）：v1 三包不向任何 npm registry 发布，唯一消费形态为 monorepo 本地引用（仓库内 `pnpm --filter`、跨仓库 `file:` 协议 / `pnpm link`）；registry 发布（公有/私有）为后续独立功能。FR-013 的"发布"在 v1 语境 = 类型定义随包构建产物（dts）一同交付，不预设 registry 发布。
- 内容生产主轴（Q2 已决，2026-11-05）：v1 以程序化从零生成、参数化构建与渲染为核心路径；外部资产（glTF 等）不在 v1 实现，schema 仅预留资产组件命名空间与字段草案（含资产组件的数据在 v1 按"未注册类型"报错，属预期行为）。
- 存储与持久化（Q1 附带约束，2026-11-05）：场景数据长期期望可保存、恢复、加载；本期只交付"存储无关的自包含序列化 + 无损往返"，具体存储介质选型（文件/数据库/对象存储）与存取 API 为后续独立功能，schema 不得假设特定存储。
- 性能预算的具体数值本期不设定（宪法已规定在首版渲染管线落地后量化并写回宪法）。
- 本期场景结构为树（不支持实例共享/DAG 引用图）；循环引用必须检测并报错。
- v1 交互默认范围（Q5 已决，2026-11-05）：轨道相机控制 + 指针事件（enter/leave/down/up/click/滚轮）+ 键盘事件（标准键值）+ 相机控制变更通知（节流）；逐帧 pointermove、输入法/组合键语义、变换 gizmo、框选、拖放、手势为后续功能。
- 仓库当前无既有代码，本规格定义的是底座首个功能（绿地搭建），无迁移负担。
